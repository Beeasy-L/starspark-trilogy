## 1. 目标

**一句话：让第一次打开介绍页的人，三秒内知道「这是什么」，并且读下去不硌牙。**

拆成三条可判的：

```
① 四页不存在任何「代码里查不到的名字 / 数字」（事实层）
② 每页第一段都有一句「这是什么」，诗与说明并存（认知层）
③ 首页三根支柱的标题，读者能看懂在说什么，而不是形容词堆砌（语气层）
```

**为什么现在做**：主公 10-26 问过「PPT 的介绍写的啥，你觉得用户看得懂吗」，10-27 又问过「写的什么垃圾」。**这已经是第三次问同一件事**，说明不是个别句子的问题，是整体语气偏「自述」而非「给人看」。


### AC-5 线上一致


## 4. 风险与回滚

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| **R1** | 改文案改出了事实错误（像这次的模板名） | 高 | 每条涉及名字/数字的改动，**必须回代码里查一次**再落笔，不凭记忆 |
| **R2** | 把主公亲手写的信误改到 | 高 | 改动清单里**不含 182–192 行**；提交前 `git diff` 逐行看这封信是否被碰 |
| **R3** | 措辞改得「更精致但更看不懂」 | 中 | 每条候选都写在确认表里，主公逐条圈；不猜着改 |
| **R4** | 句子变长导致移动端换行难看 | 中 | 改完后四页首屏重量不得超过基线 ×1.1（`index 51.5 / focus 222.5 / streak 282.8 / ppt 538.4 KB`） |
| **R5** | 冻结期前改文字引发连锁 | 中 | 只改 `<p>` / `<h3>` / `<h4>` / `alt` / meta 的**纯文本**，不碰结构、不碰属性、不碰 class |

### 回滚（具体动作 + 怎么证明回滚成功）

```powershell
# 回滚：文字改动是单次提交，revert 即可
git revert --no-edit <本次提交 hash>
git push origin main

# 证明回滚成功（不是「命令没报错」）
git show HEAD:index.html | Select-String '紫雾星海'   # 期望：能搜到（说明回到了改前）
git show HEAD:projects/ppt.html | Select-String '六种气质'  # 期望：能搜到
python tools\check_html.py index.html projects\*.html       # 期望：全部通过
git rev-parse HEAD; git rev-parse origin/main                # 期望：两个哈希相同
```

**为什么能干净回滚**：本次只改纯文本，不动结构、不动资源、不动 CSS/JS，**revert 后站点与改前逐字节一致**。

## 一、主公四问，逐个给证据

### ① 「质量太垃圾」→ 最大单一来源：**图片在整个系统里不存在**

不是「图少」，是**图片这个东西压根没有被建模**。五个环节全空：

| 环节 | 证据 |
|---|---|
| 数据模型 | JSON 只有 `title / subtitle / slides[{title, layout, content, note}]` —— **没有图片字段**（`server.py:421-429`） |
| 版式库 | 12 种版式，**0 种有图位**（`server.py:381-393`） |
| 渲染层 | 全仓 `<img` 命中 **0 处**、`background-image` **0 处**（`static/index.html` 全文） |
| 上传层 | **主动拒收图片**：`toast("图片参考暂不支持")`（`index.html:600`）、`server.py:93-94` 返回「已忽略」 |
| 导出层 | 只有 `add_textbox` / `add_shape`，**没有 `add_picture`** |

**后果**：一份含「产品界面 / 人物 / 场景 / 实验对象」的 deck，只能全部变成「深色底 + 标题 + 几行字」。
**在用户眼里，这就等于「AI 帮我把文字重新分了行」。**

**顺带两个加重病情的细节：**

- **9 种内容版式共用同一个头部**（`.pt` 标题 + 40px 渐变短线，`index.html:2089`）→ **版式名不重复，观感照样雷同**。这比「同一版式用两次」严重得多。
- **唯一的装饰层 `.deco` 什么也不画** —— `.page.cover .deco` 只写了 `position/inset/pointer-events`，**没有 background**（`index.html:217`）。那个 div 是空的。

### ② 「格式不正确」→ 三个硬伤，其中一个直接毁掉体验

#### 🔴 硬伤 A：**「导出 .pptx」下载到的其实是 `.py` 脚本**

```
按钮文案：导出 .pptx
实际下载：星火PPT-生成.py        ← index.html:2264
提示语自己承认：需装 Python + pip install python-pptx
```

**主公说的「格式不正确」，第一观感极可能就来自这里** —— 点了「导出 PPT」，拿到一个双击打不开的文本文件。

#### 🔴 硬伤 B：**autoFit（溢出自动缩字）在最常用的版式上完全无效**

`autoFit` 溢出时会设 `--k` 让字号降档（`index.html:2059-2067`），但——

**`--k` 全站只被「页码」一个元素消费**（`index.html:203`）。

```css
.pno     { font-size: calc(11px * var(--k,1)); }   ← 只有它响应
.pt      { font-size: 4.079cqw; }                  ← 标题不响应
.ulist li{ font-size: 1.447cqw; }                  ← 正文不响应
.pnote   { font-size: ...; }                       ← 收束句不响应
```

而 `.page{overflow:hidden}`（`index.html:177`）。

**后果**：要点页内容一多，autoFit 循环 6 次，**唯一变小的是页码，正文被直接裁掉**。
这就是用户看到的「文字被切了 / 压边了」。

（two_col 只有 h4 响应、正文不响应；compare 只有 h4 响应、条目不响应。其余 9 种响应正常——**所以这个 bug 恰好落在最常用的三种版式上**。）

> 更新日志里写着「溢出自动降档」，**这句是真的实现了，但接错了元素**。

#### 🟠 硬伤 C：**提示词与渲染器互相矛盾（3 处）**

| 现象 | 根因 |
|---|---|
| 两栏页的右栏小标题，变成左栏的一条正文 | 提示词说「第 1、2 条是小标题」（`server.py:385`），渲染按 `ceil(n/2)` 切（`index.html:2115-2119`） |
| 金句页顶部**永远印着字面「一句话」**，且**整页标题被丢弃** | `index.html:2094` 读 `s.eyebrow`，但 schema 没有这个字段、编辑面板也没输入 → 100% 走兜底；pptx 侧更离谱，是英文 `"A WORD"`。而且金句分支提前 return，**AI 认真写的页标题被渲染层扔了** |
| 表格没有表头，第一行数据看着像表头又不像 | `index.html:2111` 只输出 `<td>`，`.tbl th` 是**死样式**（`index.html:277`）；LAYOUT_DOC 也没规定要不要表头 |

### ③ 「模板太少」→ **准确说是「根本没有模板，只有 6 套配色」**

他现在的 `TPL` 只有 `{id, name, cls}`（`index.html:546-553`），切模板只改 CSS 颜色变量。
**字体、标题位置、列表样式、装饰、间距——全共用一套。**

而且 `--deco` / `--tcard` / `--tcardh` 三个变量**定义了但零引用**——所谓「主题」连自己声明的变量都没用上。

**更重要的发现**：官方规范里**真的有 30 套设计系统**（5 族 × 6，每套一份 `design.md`，含配色/版式骨架/字体/图表语言/签名组件/禁令/密度基线），实测 30 个文件都在。

**所以问题不是「他做得少」，是「规范里那 30 套他一套都没用」。**

### ④ 「诗词只有 1 句」→ 确认，比主公以为的更少

全产品只有**一处**硬编码诗：`index.html:2140` 的「星星之火，可以燎原」——
而且它在**封底 content 为空时的兜底分支**里，**大多数情况根本不会显示**。

**也就是说：实际不是「只有 1 句」，是「通常 0 句」。**

我已交付 30 句给他：`星月诗笺-30句-致星火PPT.md`（含**「不能照搬我的按日期轮换逻辑」**的说明——PPT 不是每日读物）。

## 二、还有三个他没发现的

审计还挖出三条，主公没提但影响体验：

1. **「流式逐页生成」其实不是流式**
   `parseStreaming` 先整份 parse，失败后**用同一个字符串再 parse 一次**，必然抛同样的错（`index.html:1991-1999`）→ **整份 JSON 到齐前页面一片空白**，用户干等 20 多秒没有任何反馈。

2. **`checkRenderer`「12 版式全过」不能当质量证据**
   它只检查输出 HTML 里**是否含某个 CSS 类名子串**（`index.html:2143-2154`），不查几何、不查条目数、不查是否溢出。上面所有缺陷它一个都照不出来。**所以「自检全过」是真的，但没意义。**

3. **预览与导出的版式别名不同步**
   `normLayout` 认 `number/title/list/quote_page` 等别名（`index.html:2076-2078`），pptx 侧 `ALIAS` 不认（`index.html:2525-2527`）→ **预览正常、导出静默降级成要点页**。

## 三、方案：按「用户感知强度」排，不按难度排

### 第 0 批：先修「一眼就觉得坏了」（0.5 天，改完主公立刻能看到差别）

| # | 修什么 | 改哪 |
|---|---|---|
| 0-1 | **「导出 .pptx」要么真给 .pptx，要么改文案** | 见下方建议 |
| 0-2 | **autoFit 接对元素**：`.pt / .ulist li / .tc-col p / .cmp-item / .pnote` 全部乘 `var(--k,1)` | `index.html:203-236` |
| 0-3 | 金句页：补 `eyebrow` 进 schema+编辑面板，或删掉兜底；**并把页标题还回去** | `index.html:2094` |
| 0-4 | 表格首行渲染 `<th>` | `index.html:2111` |
| 0-5 | `two_col` 渲染按「前两条是小标题」实现（与提示词对齐） | `index.html:2115-2119` |
| 0-6 | pptx `ALIAS` 与 `normLayout` 同步 | `index.html:2525-2527` |

> **0-1 的具体建议**：前端引 `pptxgenjs`（CDN，单文件仍成立）**直接产出真 .pptx**。
> 若暂时做不到，**至少把按钮文案改成「导出 .pptx 生成脚本」**——
> **按钮上写的必须等于下载到的东西。** 这是信任问题，不是功能问题。

### 第 1 批：把「图」这条命脉打通（2~3 天，这是质变）

**这是「垃圾感」的最大单一来源，不做这一批，其余全是化妆。**

| # | 做什么 |
|---|---|
| 1-1 | schema 增 `image: {kind, query}`；AI 只负责判断「这页要不要图、要什么图」 |
| 1-2 | 新增 2 种版式：`image_full`（整幅图+底部文字条）、`image_side`（**非对称**：图 55% / 文 45%） |
| 1-3 | 渲染层 `object-fit:cover` + `aspect-ratio` 锁死，**严禁拉伸** |
| 1-4 | 上传层**改为收图**（现在是主动拒收），存 `media/` |
| 1-5 | 图源优先级：**用户上传 > 官方/权威 > 检索 > 生成**；无图源时 `image` 字段留空，**不许放凑数图** |
| 1-6 | 单文件约束下的现实路径：**先只做「用户上传图」+「留白不配图」两态**，不引入联网搜图 |

> **给主公的一句话**：1-6 是关键取舍。**不联网搜图**是这个项目的底线（和你第二部一样），
> 所以「图」只能来自**用户自己上传的素材**。这不丢人——**用户自己的图，比网上搜的更相关**。
> 规范本身的第一优先级就是「用户材料优先」。

### 第 2 批：模板从「6 套配色」升为「族 + 主题」（2 天）

**关键结论：不要照搬 30 套，做「5 族语义 + 15 套主题（5×3）」。** 三条硬理由：

1. **8 套强依赖摄影**（如 pine-soot-pictorial / silver-gray-luxury-magazine / moon-white-imagery）——**没有图源时选中它们，产出比现在 6 套更差**。
2. **9 套需要特殊字体**（Archivo Black / Anton / Inter / Unna / Oranienbaum…）——字体不到位，视觉签名退化成「只有配色」，**正是主公批评的那个病**。
3. **30 套全部禁「等分构图」与「卡片」**，而现有 `grid / two_col / kpi` 本质就是等分与卡片墙 → **照搬会让规范与版式库互相否定**。

**做法**：
- 现有 6 套不废，**归位到族**并补「人格层」（字体/密度/线条/装饰），而不是只换色
- 每族取 3 套，共 15 套；**每套 = 22 个 CSS 变量的令牌契约**（规范里已提炼好）
- 内置「7 场景 → 族」映射表，**不让 AI 自由猜族**

### 第 3 批：结构视觉与诗词（2 天）

- 分场景页序（取规范真实骨架，不再用他自己拍的 6 条大纲）
- 补 5 个高频页型：`section_opener / agenda / heat_table / waterfall / decision_tree`
- `grid` 从等分改为非对称比例（31:38:31 / 58:42 / 64:36 / 72:28）
- **30 句星月诗接入**（我已交付，按「位置 + 气质」选，不按日期）

### 第 4 批：可量化的自检（1 天）

- 把 `checkRenderer` 从「查类名子串」升级为**查几何**（溢出 / 越界 / 重叠 / 字阶比）
- 跑 10 份不同主题的 deck，统计**改前/改后**：版式契约失败率、溢出页数、可见诗词数、真模板数

## 四、验收指标（不靠感觉）

| 指标 | 现状（实测） | 目标 |
|---|---|---|
| 「导出 .pptx」产物 | **是 .py 脚本** | 真 .pptx，或文案如实 |
| autoFit 生效版式 | **3 种无效**（bullets/two_col/compare） | 12 种全生效 |
| 图片通道 | **0（且拒收）** | 用户上传图可用，2 种图文版式 |
| 契约矛盾 | 3 处 | 0 |
| 真模板（非配色） | 0（6 套仅配色） | 15（5 族 × 3） |
| 一份 deck 可见诗词 | **通常 0 句** | 2~3 处 |
| 用户等生成时的反馈 | **空白 20 秒** | 逐页出现 |

## 五、我要说的话

**主公那句「我为什么不去直接用 AI」，答案是：**

因为直接问 AI，你拿到的是**一段文字**。
而这个产品应该给你的，是**排好版、配好图、分好场景页序、能直接拿去讲的一页页东西**。

**现在它做的，恰好就是「把 AI 那段文字重新分了行」** —— 所以主公的感觉是准确的，不是苛刻。

**要变，必须做第 1 批（图）。不做这一批，第 0/2/3 批全是化妆。**

## 六、给主公的决策点

1. **第 1 批的取舍**：`image` 只支持「用户上传」，不联网搜图 —— **准不准？**（我建议准，符合项目底线）
2. **模板数**：15 套（5×3，我建议）还是星火PPT 原计划的 12 套？（12 套仍可能只是「12 种配色」）
3. **「导出 .pptx」**：引 `pptxgenjs` 做真 .pptx（约 1 天），还是先只改文案？
4. **优先级**：主公要的是「先能看」（第 0 批半天）还是「彻底翻新」（第 1+2 批约 5 天）？

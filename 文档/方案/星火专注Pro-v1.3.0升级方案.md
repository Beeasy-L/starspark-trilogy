## 一、v1.3.0 要解决什么（一句话）

**v1.2.3 是止血；v1.3.0 是把「已经存下来的东西」真正还给你。**

三条痛点，都不是新功能，是**档案正在过期**：

1. **信笺匣只显示最近 30 封** —— 第 31 封起永远看不到，但数据还在库里
2. **星链只有 90 天窗口** —— 三个月前的单条记录全站不可达
3. **库里躺着 5 个字段从没露过面** —— `onTime`（是否准时入座）、`completedRatio`（完成度）、`endedBy`（自然完成 vs 手动收束）、`successDays` / `missedDays`（累计守住/失守）

**第一批长期用户正走到第 30 天 / 第 90 天，他们的信和早期记录正要开始消失。这是现在做它的理由。**

## 二、五个工作流（可独立交付、可独立验收）

### 【A】信笺匣：30 封 → 全部（含分年折叠）

**现状**（已核实）：
```
line 2931  const keys = Object.keys(S.reviews).sort().reverse().slice(0,30);   ← 信笺匣
line 2962  const keys = Object.keys(S.reviews).sort().reverse().slice(0,14);   ← 最近复盘
```

**改什么**：
- 去掉 `slice(0,30)`，改为按年分组折叠（`2026 年（87 封）` / `2025 年（240 封）`），默认展开当年、其余折叠
- 「最近复盘」保留 14 条不封顶——那是速览，不是档案
- 信箱页顶部加一行统计：`共 N 封 · 从 YYYY-MM-DD 写起`

**成本**：~40 行　**风险**：低（只读展示）

**验收**：造 100 天数据 → 信笺匣能翻到最早一封；DOM 里存在 31 封以上

---

### 【B】星链与星图：90 天 → 全部

**现状**（已核实）：
```
line 2259  const items = S.blocks.slice(-60);          ← 星链长卷只渲染最近 60 颗
line 2389  const recent = S.blocks.slice(-40).reverse();  ← 最近记录 40 条
line 2441  for (let ago=89; ago>=0; ago--)              ← 星图只画 90 天
```

**改什么**：
- **星链长卷**：`slice(-60)` → 分段加载。**不一次性渲染全部**——1000 颗星一次渲染会卡
- **星图**：90 天窗口保留（它是「最近状态」视图），**另加「全部年月」选择器**：`2026-10 / 2026-09 / …`
- **最近记录**：`slice(-40)` → 可按月浏览

**成本**：~90 行　**风险**：中（渲染性能，需实测 1000 颗星）

**验收**：造 500 颗星 → 长卷能滚到第 1 颗且不卡；星图能切到任意历史月

**性能红线**：单次追加渲染耗时 < 80ms（低端机），超了改虚拟滚动

### 【C】把 5 个字段接出来

**现状**（已核实，全部「只写不读」）：
```
onTime           出现 5 次   —— 全是写入/初始化，无读取
completedRatio   出现 2 次   —— 全是写入
endedBy          出现 3 次   —— 全是写入
successDays      出现 3 次   —— 只参与计算，不展示
missedDays       出现 3 次   —— 同上
```

**接到哪里**（关键是**别做成数据报表**）：

| 字段 | 接到 | 表述方式 |
|---|---|---|
| `onTime` | 单颗星详情卡 | 「准时入座」小标记（只在预约来的星上显示） |
| `completedRatio` | 单颗星详情卡 | 「完成度 92%」——**只在 < 100% 时显示**，满完成不罗列数字 |
| `endedBy` | 星链统计卡 | 「完整走完 N 次 · 你主动收束 M 次」——**中性表述，不评判** |
| `successDays` / `missedDays` | 国策节点卡 | 「累计守住 42 天 / 失守 6 天」 |

**成本**：~50 行　**风险**：低

**验收**：点开一颗预约来的星能看到「准时入座」；国策节点显示累计天数

---

### 【D】信里带上当天的星

**现状**：信 = 复盘三栏（好事/Idea/Thinking）+ 一句诗。**当天专注成绩一个字没有。**

**改什么**：信尾加一段（数据全在 `S.blocks[]`，按 `dayKey(endedAt)` 筛当天）：
```
—— 这一天你铸了 3 颗星，坐了 75 分钟，
   链走到第 47 颗。最久的一段是《线性代数》。
```

**关键约束**：当天没点火时写 **「这一天你没有点火——但它也是你的一天」**，**不出现任何「未完成/失败/可惜」字样**。

**成本**：~30 行　**风险**：无

**验收**：打开一封有 3 颗星的日子的信，能看到成绩；打开一封没点火的日子，看到中性措辞且不含否定词

---

### 【E】清理星链 73 行死代码

**现状**：`line 2516 function renderChainNet(){...}` —— 定义 1 次、**调用 0 次**；它要写的容器 `#chainNet` 在 HTML 里根本不存在；配套 22 行 CSS 与 `#starGlow` 滤镜都只在这段死代码里。

**改什么**：删掉 `renderChainNet` + `currentChainBlocks` / `curvePoint` / `starPath` / `starTitle` / `showStarDetail` 簇 + 配套 CSS。**顺手删 `window.__chainNoGrow`**（被读 3 次、赋值 0 次，恒 undefined，导致每次进星链都重放 60 颗星动画）。

**为什么推到现在**：它就在【B】要改的区域里，一起动一次即可。

**成本**：删 ~95 行　**风险**：低但需确认无隐藏引用（删前 grep 全部符号）

**验收**：星链页功能不变；首屏少解析约 4 KB；进星链不再重放全量动画

## 四、v1.3.0 **不做**什么（这条比做什么重要）

| 不做 | 理由 |
|---|---|
| 排行榜 / 与他人对比 | 专注是私事。一旦能比较，就会有人为数字而坐 |
| 打卡提醒 / 推送通知 | 「今天还没专注」本质是催促。产品文案写着「不拿它催促你」 |
| 账号 / 云同步 | 数据只在你设备上是**承诺**，不是妥协 |
| AI 生成内容 | 无服务器；且「你的事只有你能写」是信的前提 |
| 徽章墙 / 成就系统 | 会把「我在长」变成「我在收藏」 |
| 断链惩罚性提示 | 已经只记最长、不羞辱，再加就是走回头路 |
| 周报式数据报表 | 【C】接字段时只做中性陈述，不做「达标/未达标」 |
| 社交分享 | 同上，私事 |


**v1.3.0 需在 ③ 里新增的断言**：

| 断言 | 方法 |
|---|---|
| 信笺匣能翻到最早一封 | 造 100 天 reviews → 断言信条目 ≥ 31，且最早日期可见 |
| 分年折叠正确 | 造跨年数据 → 断言出现两个年份分组 |
| 信里有当天成绩 | 造 3 颗星的日子 → 打开信 → 断言含「铸了 3 颗星」 |
| 没点火的日子措辞中性 | 造空日子 → 断言不含「未完成/失败/可惜」等否定词 |
| 字段接出 | 造预约星 → 详情卡含「准时入座」 |
| 星链能滚到第 1 颗 | 造 500 颗星 → 滚到左端 → 断言第 1 颗节点存在 |
| 死代码已删 | 断言 `renderChainNet` 与 `__chainNoGrow` 在源码中不存在 |
| 体积预算 | gzip ≤ 80 KB（当前 68.8 KB，余量 11.2 KB） |

**另两条人工核对**（脚本验不了）：
- 造 1000 颗星时星链页**不卡**（帧率 / 滚动流畅度）
- 所有新文案**通读一遍**，确认没有一句是「评判性」的

## 七、请主公定的一件事

**【B】的分段加载策略**：

- **方案甲**：滚到左端自动加载下一段（无缝，但实现复杂、边界多）
- **方案乙**：按年分页，用户点「更早一年」（简单、可预测，但多一次点击）

**我倾向乙。** 理由：星链是「证据」，不是「信息流」——用户翻早期记录是**有目的的回看**，不是无目的滑动；分年更贴合「回看某一段时间」的真实意图，也不会出现「滑着滑着突然加载」的打断感。

**这条定了我才动【B】。**

## 二、图片是否拖慢首屏 —— 是，且根因不是图片大小

单资源耗时（Performance API resource timing）：

```
ppt-pages.jpg     155 KB   4,452ms   ← 全场最慢
ppt-themes.jpg     73 KB   2,442ms   ← 更小反而更慢
ppt-compare.jpg   114 KB   1,625ms
spark-morning.webp  77 KB   1,180ms
focus-today.webp    51 KB     616ms
```

**curl 独立复测（绕开页面）：**

```
ppt-pages.jpg    1.89s / 158KB
ppt-themes.jpg   1.32s /  74KB     ← 一半体积，耗时几乎一样
第二次拉 ppt-pages.jpg 仍 1.42s    ← 不是冷缓存
```

**结论：GitHub Pages 从国内网络取每个请求都要 1.1~2.3 秒，与文件大小基本无关。** 慢的是「每请求延迟 × 请求数」，不是图片体积。ppt.html 有 5 张图 + 1 张 CDN 图，所以最慢。

**这与 10-28 分享卡的测速结论同源**（当时 Pages 1,099~1,385ms vs 自建服务器 58~86ms）。

## 四、写信折叠块展开（首页「启封」）

```
展开前 .epilogue-body 高度:      0 px
展开后:                       1029 px   ✅ 折叠真的生效
容器整体:                     163 → 1182 px
动画期间帧数: 53   p50: 21.5ms   p95: 66ms   最差帧: 78ms   >32ms: 14 帧
```

**判定：PASS（有轻微掉帧）。** 0.85s 的 `grid-template-rows` 过渡中，14/53 帧超过 32ms、最差一帧 78ms——**展开瞬间能感到一点点不丝滑，但不卡死、不闪烁**。原因：信体 11 段文字 + 加粗混排，浏览器在过渡中持续重排。

## 七、汇总

| 项 | 判定 |
|---|---|
| 首页 / focus / streak 加载 | **PASS**（1.7~2.1s） |
| **ppt.html 加载** | **WARN：4.1s**，根因 = Pages 每请求 1~2s × 6 张图，非图片体积 |
| 四页滚动 | **PASS**（无一帧 >50ms） |
| 折叠展开 | **PASS**（0→1029px，最差帧 78ms，轻微掉帧） |
| 音乐起播/切歌/淡入/不切回 | **PASS，零卡顿** |
| 长任务 | 首页 270ms、ppt 4 个最长 337ms（site.js 初始化 + 图片解码） |

## 八、可选项（只报不改，等主公定）

1. **ppt.html 若要求 <2s**：把 5 张图减到 3 张（去掉 pages/points 其一），或给全部 `<img loading="lazy">` 加 `decoding="async"`——但根因是 Pages 延迟，减请求数才是真解。
2. **折叠展开的 14 帧掉帧**：可给 `.epilogue-inner` 加 `content-visibility:auto`，代价是展开瞬间可能闪白。**不建议在发布前动。**

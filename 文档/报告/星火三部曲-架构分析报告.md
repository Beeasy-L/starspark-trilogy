## 三、架构层面的五项真实问题

### 问题 A（最高优先级）：`design-tokens.js` 与 `pdf-extract.js` 悬空
**证据**：`design-tokens.js`（实测 56,516 B）与 `pdf-extract.js` 15,335 B 存在于 `dev/`，但 `static/index.html` 中搜索 `design-tokens|design_tokens|XH_DESIGN` → **0 命中**。

**这意味着什么**：主公想要的「内置优秀 Skill、动画精美、别具一格」，其**设计语言的地基没有被运行时使用**。

**⚠️ 成本更正（2026-10-26，经验收官核正、架构师复测）**：
- `design-tokens.js` **不是一套 CSS 变量，是一个导出了 `window.XH_DESIGN` 的数据表**（每个数值带 `src` 出处），文件内 `--fs-*` **0 个**
- 因此**不存在「两套命名并存」的问题**（该项系架构师误述，已作废）
- 主程序 CSS 变量是**定义次数 430、去重后唯一 89 个**（`:root` 内 20 个）。430 是定义次数，不是变量个数

**真实工作量**：不是「两边对齐 430 个变量」，而是**单向引入**——把 `XH_DESIGN` 里的实测数值挂到现有 89 个唯一变量上，或直接生成一份新 `:root`。**量级约为先前估计的 1/5，且方向不同（引入而非对账）。**

**建议**：不是简单 `<script src>`（单文件部署形态要求内联），而是做**「tokens → 主题生成器」**：`XH_DESIGN` 作为唯一真源，由构建脚本生成 `index.html` 里的主题 CSS 段。零运行时开销，保持单文件形态。

### 问题 B：音画不同步——主公目标的核心缺口
**证据**：BGM 的 `duckOn/duckOff` 只在 L6220/L6287/L6406/L6461 四处，**全部位于 AI 生成流程**。翻页与元素出场动画路径上无任何 duck 调用。

**建议**：新增「动画编排层」，翻页/出场时序事件总线，动画开始 duck、结束 duckOff。这需要动画层可监听——当前 `requestAnimationFrame` 仅 3 处、`@keyframes` 3 处、**无 Web Animations API（`.animate(` 0 命中）**，说明动画目前是**零散 CSS 类切换**，没有一个统一调度层。

**这就是「动画编排 Skill」的落点**：不是加特效，而是先建一个能发事件的动画调度层。有了调度层，音画同步、三档速度、全局关闭才能落地。

### 问题 C：跨产品 0 契约 —— 三部曲仍是「三件成品」
**证据**：
- PPT 主题名与专注Pro/介绍页无共享定义
- 无任何归档/导入导出格式
- 介绍页内置 focus-app 是 10-24 旧版（211 KB vs 230 KB）
- 各自独立 git，续火花工作区甚至**无 git**（`git log` 报 `not a git repository`）

**建议**：这是本报告认为**最该做且成本最低**的一步——
1. `spark-common` 静态资产包（design-tokens 作为真源，专注Pro 也要用）
2. `.spark` 归档格式（专注Pro 导出 / PPT 导入片段）
3. 介绍页版本同步脚本（解决 C 的第三例）

### 问题 D：单文件形态 vs 8 模块的长期张力
`static/index.html` 已 377 KB / 6,760 行 / 430 个 CSS 变量。dev/ 里有 8 个模块，运行时是一坨内联代码。

**风险**：每加一个 Skill 就往主文件里塞一段 → 6,760 行继续膨胀，验收官每次都要全文审；已出现的现象是 `index.html` 里 L1657 出现 `const TPL = [ ...原有 6 项..., ...window.XH_TEMPLATES_EXTRA ]` 这种**手写拼接痕迹**。

**建议**：不推翻单文件（用户可双击打开、无构建依赖是真实优势），但引入**构建期合并**：`dev/*.js` 是真源，`build.py` 合并 + 压缩 + 哈希 → `static/index.html`。这样 Skill 化才可持续，且能顺手解决"deploy 与 source 手工同步"的隐患。

### 问题 E：工作区卫生
30+ 个 `_edge*` / `_tmp_*` / `__pycache__` 目录，另有 `_disc.py` `_iso.py` `_p0test.py` `_full.pptx` 等散落文件。

**风险**：真源与实验副本混杂，验收官/新人极易误读。`_edgeP0`（10-26 12:12）与 `_edgePptx`（10-25 17:13）看起来是**正在进行的 pptx 导出验证实验**。

**建议**：归档 `_*` 到 `_archive\`，真源目录白名单化（`星火PPT\static`、`dev`、`server.py` 等）。

## 五、建议的落地顺序（不动现有成果，全部增量）

### 第二阶段：建动画编排层（主公目标的核心）

6. **音画同步**：动画开始 duck、结束 duckOff（挂到新调度层，而非生成流程）
7. **动效语言统一**：统一缓动曲线族，禁用弹跳/闪烁类廉价特效

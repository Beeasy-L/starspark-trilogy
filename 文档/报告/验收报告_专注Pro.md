## 二、验收范围详情

### 2.1 代码质量审查

#### 优点

1. **CSS变量体系完善**（第13-25行）：定义了全部设计令牌（`--bg`, `--gold`, `--ink`, `--serif` 等），色彩一致性极好。
2. **模块化注释清晰**：CSS 和 JS 均按功能区用 `/* ===== 区块名 ===== */` 分隔（点火仪式、国策树、星链、备份中心等），3556行代码可读性高。
3. **数据持久化设计优秀**：
   - 主存储 `localStorage` + 自动快照机制（`AUTO_KEY`，最新+最近6份历史）
   - 损坏时自动从快照自愈（第1148-1156行），坏档另存为 `__corrupt`
   - 恢复前先另存 `__pre_restore`（第3118行），容错到位
4. **状态规范化**（第1167-1177行 `normalizeBlock`）：自动为旧数据补全字段（`completedRatio`、`endedBy`），向后兼容好。
5. **防漂移计时**：使用真实时间差（`Date.now() - startTs`）而非 `setInterval` 累加，锁屏/切换后台后时间准确。
6. **字体处理**：部署版本字体外置（`_web/build_font.py`），HTML从内嵌字体变为196KB纯文件。

#### 发现的问题

| 编号 | 严重程度 | 位置 | 描述 | 建议 |
|------|----------|------|------|------|
| C01 | 🟡 中 | 第1151行附近 | `loadInitialState` 的 try-catch 分支中直接使用了未在当前作用域声明的 `AUTO_KEY`——它在外部已声明，但异常分支的代码路径缺少显式校验 | 确认 `AUTO_KEY` 声明在所有引用之前，或添加 defensive check |
| C02 | 🟡 中 | 第1173行 | `normalizeBlock` 中 `ratio >= .8 && ratio < .995` 这一行：`done` 状态在满足 .8 时被改回 `settled`，可能导致通过 `setTimeout` 模拟的完整完成被误判 | 增加注释说明这是"人工而非计时器完结时按进度归类"的语义 |
| C03 | 🟢 低 | `blocksByDay` 函数 | 每次渲染都遍历全量 `S.blocks`，当用户积累数百条记录时，90天星图渲染可能变慢 | 可考虑对 `blocksByDay` 做 memoize（仅在 blocks 变更时重算） |
| C04 | 🟢 低 | 第1772行 | 烟花粒子使用 `setTimeout(2400)` 清理，大量粒子时可能累积未清理节点 | 确认在 `finish()` 中（第1791行）`mask.innerHTML=''` 已兜底清理 |
| C05 | 🟢 低 | `annualStats` | 月度柱状图中 `maxM` 取值 `Math.max.apply(null, st.months.concat([1]))` 在12个月全为0时会有除以1的效果，但柱高24px无意义 | 全为0时直接返回空数据提示 |

### 2.3 UI/UX 质量审查

#### 配色方案
- **深色星空背景**（`--bg: #0D1226`）+ 径向渐变模拟星云（第30-33行），配固定星星SVG
- **金色高亮系统**：`--gold: #F2C66D`、`--gold-hi: #FFD98A`、`--gold-deep: #C9943F`，用于标题、按钮、选中态、统计数据
- **蓝调辅助**：`--blue: #82A6FF`，用于链接、判例、冻结态
- **橙红警示**：`--ember: #E8915B`，用于断链、未做到
- **评级：优秀** ⭐⭐⭐⭐⭐ — 色彩语义一致，对比度充足

#### 字体
- 衬线：`Noto Serif SC`（标题、诗词、公式、星链数字）
- 无衬线：`Noto Sans SC`（正文、按钮、UI控件）
- 等宽：系统 monospace（计时器数字）
- **评级：优秀** — 中西文搭配得当，字重分级清晰

#### 响应式设计
- 桌面端（≥860px）：`max-width: 820px` 居中，顶部导航，无底部栏
- 移动端（<860px）：`max-width: 760px`，底部5标签导航（`bottomnav`），带 `safe-area-inset-bottom`
- 按钮热区：QA验证 ≥44px（M02: 61px），触控友好
- 字间距自适应：`letter-spacing` 使用 `em` 单位
- **评级：优秀** — 横溢测试通过（M01/M03/M05/M09: 0px溢出）

#### 可访问性
- `prefers-reduced-motion` 支持（第413-415行，第1807行），减弱动画
- 低端设备检测（`deviceMemory <= 4`，第1808行），减少烟花粒子
- SVG元素有 `aria-label`（星图日历按钮）
- **评级：良好** — 降低了动效强度但未提供完整键盘导航和高对比度模式

## 四、改进建议（未来版本）

### 4.1 工程化建议
1. **拆分源文件**：当前 3556 行单文件虽部署方便，但维护时 CSS/JS/HTML 混在一起。建议源码拆分为 `style.css` + `app.js` + `index.html`，通过 `_web/build_font.py` 同类脚本构建为单文件部署版。
2. **添加版本号水印**：在 `S.meta` 中记录 `appVersion`，导入备份时可做版本兼容判断。
3. **简单 CI**：利用现有 `_web/e2e_v030.py` 和 `_shots` 工具链，加上 GitHub Actions 自动截图对比。

### 4.2 功能增强建议
1. **深色/浅色模式切换**：当前仅深色模式，可加 `prefers-color-scheme` 支持。
2. **专注时段热力图**：利用现有 `blocks` 数据，生成一周每小时分布热力图（类似 GitHub 贡献图）。
3. **成就系统**：利用已有的 `chain.bestNo`（最长链）、`startup.bestNo`（最长启动）触发里程碑动画（已有 `mile-banner` 组件）。
4. **星链分享卡片**：类似年度星图的 Canvas 绘制，生成"当前星链"分享图。

### 4.3 测试建议
1. 安装 Playwright 消除 `engineDegraded` 降级，获取更准确的E2E截图
2. 对 `normalizeBlock`、`rebuildChain`、`annualStats`、`importPreview` 编写独立单元测试
3. 增加 localStorage 满负荷测试（模拟 5MB 限制）
4. 在 Firefox 和 Safari 上运行至少一轮冒烟测试

# douyin-cloud-streak 项目经验总结（截至 V5.0）

> 星火续火花工具 · 作者 Esty · 主题「心栖明月长明」（月夜猫）
> 这份文档沉淀从 V1.0 到 V5.0 一路踩坑、修复、迭代得到的**可复用经验**，供后续继续开发的人/AI 直接参考。
> 维护原则：**先看证据、原因级修复、最小改动、零新增依赖、绝不静默降级、绝不甩锅用户。**

---

## 一、项目是什么

- 帮用户在抖音里给勾选的好友/群聊**每天定时自动发消息续火花**，支持云端 24 小时挂机（阿里云 Ubuntu，systemd），网页端（手机/电脑）管理。
- 核心能力：登录态扫码、同步联系人与火花天数、定时多时间点发送、语库问候 / AI 问候（日常 / 新闻早报 / 智能接话）、火花四态识别、失败告警、备份恢复。
- 用户画像：**零基础、纯小白、自己点一键脚本部署**，要求开箱即用、中文、出错有大白话提示。

## 二、技术栈与硬约束（不可轻易突破）

| 维度 | 选型 / 约定 |
|---|---|
| 后端 | 纯 Python（标准库优先；Playwright 做抖音网页自动化） |
| 前端 | **单文件 `static/index.html`**，Element Plus 本地 vendor，无构建步骤 |
| 依赖 | **零新增依赖是红线**：能用标准库（urllib/http.client/json…）就不许 pip install |
| HTTP | 早期 urllib；V4.4 起 AI 调用改用 `http.client` 以区分连接/读取超时 |
| 数据 | 本地 JSON 台账（`data/账号/*.json`），旧数据**零迁移、原地补齐字段** |
| 部署 | 一键菜单（`①一键开始`），[2] 整站更新；打包忽略 `data/venv/__pycache__`，**更新不覆盖 data/登录态、不要求重新扫码** |
| 云端 | 阿里云成都（8.137.60.56，2vCPU/2G），systemd `douyin-cloud-streak`，端口 8000 |
| 版本 | 一位小数（4.0 可带小补丁 4.0.3）；更新日志 docx 标题=红棕 `#B03A12`、加粗、14pt、Calibri，要点 List Bullet，版本顺序**新→旧** |

## 三、目录与关键模块

- `①一键开始/`：部署 bat、更新日志.docx（面向用户）。
- `②程序文件/`：
  - `app.py`：HTTP 服务与全部 API（鉴权、账号、台账、AI、备份、扫码、发送触发）。
  - `core/automation.py`：**发送主链路 `run_send`**、浏览器操作、群聊/单聊通道、火花提取 JS、`MessageSendTracker`。
  - `core/ai_greet.py`：AI 问候（日常/接话/早报）、`_chat`/`_post_once`、`_prefetch_morning`、重试与清洗。
  - `core/morning_report.py`：早报素材（新闻+天气+农历+微语），高德 Key 与免费源、城市去重/负缓存。
  - `core/phrases.py`：本地语库选句、占位符渲染、节日/节气优先、去重。
  - `core/festival.py`：节日/节气本地引擎。
  - `core/ledger.py`：好友台账、火花四态合并、发送记录、城市字段。
  - `core/browser.py`：`open_browser` 浏览器池/名额；`core/runtime.py`：运行锁；`core/guard.py`：风控检测；`core/backup.py`：备份（含 `APP_VERSION`）；`core/msg_builder.py`、`core/sender.py`、`core/reply_context.py`。
  - `static/index.html`：全部前端。
  - `tests/`：脚本式离线测试（无 pytest，直接 `python tests/test_xxx.py`，看 PASS/FAIL 与 exit code）。

## 四、发送主链路（改发送逻辑前必读）

定时/手动触发 `run_send(dry_run, only_names, account_id, scheduled, slot)`：
1. 校验 state.json 登录态、运行锁（代际令牌）、每日批次锁（`日期+slot` 幂等）。
2. 打开浏览器（名额→打开→登录校验→进会话页）。
3. 可选「发送前自动同步」滚动提取全员火花天数/单聊群标记。
4. 素材与文案准备：
   - AI 早报：`morning_report.build_materials` 抓素材 → `ai_greet._prefetch_morning` **分批生成**（V4.4）。
   - AI 日常/接话：`prefetch_batch` 批量生成。
   - 本地兜底：`phrases.choose_for` 每人取句。
5. 逐好友循环：幂等判断 → 单聊/群聊识别 → 选文案 → **V4.4 不降级闸门**（开早报且没生成成功则 skip、绝不发本地句）→ 通道分发。
   - `_send_consumer`：群聊强制走 consumer 私信通道；单聊按 `_route_send_channel`。
   - `_send_creator`：creator 通道。
   - 真实 `_send_consumer(page, entry, msg, dry_run, result, aid, tracker=, slot=, conv_type=, fallback_msg=)` 会带 `slot=` 关键字（**写测试桩必须接收**）。
6. 成功铁据：消息区「我方气泡 +1」（无服务端回执时也据此判定），发完校准火花天数/状态。
7. 防风控：每人之间随机间隔；整轮至少 1 人成功才上每日锁；失败/跳过写进 result 与日志。

## 六、高价值踩坑与根因（按主题）

### 1. 浏览器自动化（Playwright）
- **虚拟列表定位**：禁止 `get_by_text(名字).first` 全页找——会抓到右侧已开会话同名节点或虚拟列表里「在 DOM 但隐藏、点不动」的缓冲节点，反复点击超时、空转十几分钟。只认**左侧列表标题容器内、可见、有非零尺寸、名字精确相等**的项；没找到/不可点/校验没过就每轮向下滚动再找。
- **浏览器名额/内存泄漏**：扫码/发送结束时，**必须第一步就归还名额**，再做 `browser.close()/pw.stop()`（小内存机上这两步可能永久挂起，导致名额被占死、残留 Chromium 吃内存，最终新扫码永远排队）。关闭/驱动停止改后台限时执行、超时强杀；Context/页面用完即关。
- **群聊 vs 单聊**：群名带「(5)/（5人）」成员数，严格全等会失败。单聊保持最严全等（防「小美」错发「小美酱」）；群聊剥尾部成员数后比对。成功铁据=「我方气泡 +1」，不要点群公告/群名当输入框。
- **长文本输入**：多行早报逐字 `keyboard.type`（每字 30ms + Shift+Enter）会丢焦点、填不进框。改为 `execCommand` 一次性注入（触发 beforeinput/input、insertLineBreak 换行），失败再回退逐字；单行短问候路径不变。
- **二维码/扫码卡死**：名额获取加超时；扫码启动加超时与内存不足闸门；看门狗按人数超时兜底，云端自动重启、systemd 拉起。

### 2. 并发与锁
- **重复发送**：Windows 单实例锁曾因进程启动时间指纹恒为空而失效，多个后台同时发。修：锁校验进程启动指纹、PID 复用/旧进程退出可安全接管；加「日期+时间点」批次锁与逐好友幂等，同一 slot 触发多次只发一次。
- **`release unlocked lock`**：强制重置会偷偷释放后台 worker 仍持有的锁，worker 结束再释放就报错且可能并发。修：锁引入**代际令牌**，获取/强制释放都推进代际，旧 worker 结束时发现代际已变则释放为 no-op。
- **轮询竞态（前端）**：守护榜/列表每 10 秒重建会清空勾选、冲掉刚设的城市、打断操作。修：进管理/删除/弹窗模式**暂停轮询**，切后台暂停、回前台立即刷新；慢请求加「进行中」守卫防堆积；乐观更新不被旧响应覆盖。

### 3. AI 与新闻早报（重灾区，按出现顺序）
- **免费接口 429**：同一时刻密集请求公共实例被限流。三重加固：城市去重（同城合并一次、共享结果）、成败都缓存 + 负向退避、**命中 429 全局退避 30 分钟且不切同服务商备用实例**（主备共享 IP，切换只会加剧）、相邻请求 1.3s 串行慢取。
- **早报 0/N 生成成功**：早报正文外还要套 JSON，却沿用「每条上限 token 512」，长输出被截断成非法 JSON。修：早报 token 按人数独立放大（单人≥700、每人 520 递增、封顶 8000），普通问候设置不受影响。
- **「我的要求无效」**：早报用了写死模板，没读用户在 AI 引擎设的「语气/额外风格要求」。修：早报同样注入语气与个性化要求（不编造事实、不串城市）。
- **高德 Key 报错 `INVALID_USER_KEY`**：曾误判用户填错。**教训：先查程序/版本，不要甩锅用户**。高德只需填 Key、不用填网址；Key 服务平台必须选「Web服务」（`USERKEY_PLAT_NOMATCH`）；加防呆：检测到误填高德示例地址自动恢复免费源。
- **人少成功、人多失败（V4.4 根因）**：素材抓取成功，但一次让模型给十几人写几千字，旧版只给 10 秒（urllib 的 timeout 是单 socket 操作超时，建连与 recv 共用），读阶段超时却被误报成「连接超时」，且零重试、整批作废。修：
  - **分批每批 4 人**，单批 prompt、独立调用，某批失败只影响该批；
  - `http.client` 区分**连接超时（约 12s 判活）**与**读取超时（按人数 45~120s）**；
  - 可恢复错误（连接抖动/读超时/429/5xx）指数退避重试（3s、6s，早报 2 次）；**401/403/404/422 等 4xx 立即失败不重试**；
  - 昵称规范化容错匹配（大小写/空格/零宽），歧义宁可不匹配、绝不串人；
  - **不降级闸门**：开早报的单聊好友，早报没生成成功就本轮 skip、绝不发本地语库句；日志点名、整轮全失败不锁、可手动补发。专属文案/群聊/普通 AI 问候不受影响。
- **成本/输出控制**：长输出同时要放大 token 与读超时，二者缺一不可；日志要打印 AI 返回字数、解析条数、截断/昵称不符/长度/敏感词/重复分类计数。

### 4. 火花天数（核心能力，反复出问题）
- **虚高**：接口字段 `interaction_count`（互动次数）不能当天数，消息数/未读数同理。要负向排除这些字段。
- **四态**：🔥normal 已续（红火/蓝火/蓝星球）/ 💧dying 待续（灰水滴/灰星星，数字仍是真实连续天数）/ 🌈relight 重燃中（断火做 3 天任务，历史归零）/ ⚪none 未点亮（无火花组件，归零）。
- **回填闸门**：DOM 已明确「无火花/已断」（has_spark=False）时，绝不允许接口数字再填进去。
- **倒计时≠天数**：「N 天后消失」不采纳，沿用真实天数；只有断火/无火花才清零；加载漏读沿用旧值，**绝不用 0 误清**。
- 提供「🔥 指纹」按钮导出每人图标真实代码，落盘 `spark_probe.json`，便于一次性校准。
- **平台规则**：火花需双方当天互发，工具只保证我方发出，对方不回仍变💧——这不是 bug，要在 UI/文档讲清。

### 5. 前端 / UI / 移动端
- **情感资产**：月亮+狸花猫主视觉图必须保留（满月可放其他页面），用 `object-fit:contain` 不裁切。
- **双皮肤**：一套设计 token 驱动浅色「月白清光」/深色「长夜星火」，切换只改一个属性、秒切不刷新。
- **移动端可达性**：触控不依赖 hover/精确点选；卡片第二行整宽放城市/操作；去掉固定 520px「框中框」内部滚动，整页自然滚，最后卡片停在底栏上方；窄屏顶栏图标要可见（收窄账号/副标题）。
- **弹窗尺寸**：统一响应式三档，小屏按百分比不溢出、桌面最大宽度。
- **城市/勾选"点不动/自动取消"**：根因都是 GET 漏字段 + 轮询重建；改模板内挂载 + 管理模式暂停轮询。
- **更新日志样式**：所有版本标题格式统一（红棕/加粗/14pt），新→旧排序，用户对前后不一致很敏感。

### 6. 安全与隐私（红线）
- **公网鉴权**：后端不把真实令牌写进网页；本机/localhost 免密，手机/外网必须持随机强令牌；令牌为空或出厂默认时公网一律拒绝（安全失败）；部署自动生成随机令牌。
- **备份默认排除**：`state.json` 登录态、访问令牌、AI Key 都不进备份包、不进日志；网页 Key 只显示 `sk-****` 脱敏、留空不改。
- **接话隐私**：只接单聊、群聊不接；聊天正文只在发送当次临时读取，不保存、不进备份/日志，只记条数与判定；按昵称精确匹配，宁可漏回也不串人。
- 红灯话题（借钱/危机/表白/约时间/索要联系方式）不替用户表态，引导去微信；被拦则回退保火花。

## 七、稳定的工程方法论（每次改动都照做）

1. **先留失败证据**：改动前从日志/截图/复现确认根因，根因要连成「触发条件→机制→症状」。
2. **原因级修复**：不用 sleep、盲目重试、放宽断言、吞错误、概率下降代替修复；但对**可恢复的网络抖动/限流**允许有限退避重试，对**参数/鉴权错误**立即失败。
3. **最小改动 + 后端契约零改动优先**：前端能映射就不动后端 API；旧数据零迁移、原地补字段。
4. **零新增依赖**：优先标准库实现。
5. **验证闭环（改完必须全跑）**：
   - `python -m py_compile app.py core/*.py` 全量编译；
   - 离线测试用脚本式 assert + exit code（venv 无 pytest），**打桩 `_chat/_post_once`/浏览器层，不联网**；
   - 现有 `tests/test_*.py` 回归必须全绿；
   - 涉及 UI 用 Playwright 模拟用户，桌面 + 移动双视口逐页点，控制台无报错；
   - 用「不同于生成路径」的方式回读（如 docx 插入后重新打开读标题顺序与格式）。
6. **失败可诊断**：区分错误类型（连接超时 vs 读取超时、4xx vs 5xx）、点名是谁、分类计数；`/api/status` 必须非阻塞秒回。
7. **降级策略要明确且尊重用户选择**：日常问候/接话默认回退本地语库保火花（绝不漏发）；**新闻早报用户明确要求不降级**——宁跳过也不拿普通句冒充，日志点名、不锁、可手动补发。
8. **风控第一**：建议每天 1~2 次、相邻≥2 小时；随机抖动以预定时间为中心**前后对称**（不能只往后延）；单聊严格全等、群聊剥后缀；以气泡为准不重复发。

## 八、协作与交付规范（给接手的 AI，务必遵守）

- **中文交付**，结论先行，简洁；用户零基础，给大白话和明确的下一步点哪里。
- **绝不甩锅用户**：报错先怀疑程序/版本/网络，不要说"你填错了/你配置有问题"——曾因高德 Key 误判被严厉纠正。确需用户操作时，给精确步骤。
- **用户对"卡了/光说不练/只出方案不动手"零容忍**：能直接改就改，边做边用一句话报进度，不要长时间沉默。
- 交付前真实编译、测试、页面验证；**只报告实际执行和观察到的结果**，没验证就写明未验证范围，不谎报完成。
- 用户倾向**自己部署**：改完告诉走菜单 [2] 整站更新、不用扫码；不要擅自连他服务器/改云端，除非明确要求。
- 密码、Key、登录态**绝不写进聊天、文档、记忆或备份**。
- 改前端要保留月亮猫图与既定双皮肤；版本号、更新日志格式按第二节规范。

## 九、环境与运维速查

- venv Python：`②程序文件\venv\Scripts\python.exe`（有 playwright+chromium、python-docx、requests、paramiko；无 pytest/httpx）。
- Windows PowerShell：禁 `&&`、`2>&1`、`head`、`cat`；stdout 易被吞，用 `*> 文件` 或 `2>$null | Out-File -Encoding utf8` 后再 Read；用 `& $py` 调；exit code 0 即成功。
- 云端：systemd 管理，内存软上限约 900MB/硬约 1400MB，卡死看门狗自愈、每 7 天自动重启清 Chromium。
- 防火墙放行端口、令牌、本地/公网访问规则见 README 部署章节。
- 手机看旧页面加 `?cb=时间戳` 强制刷新缓存。
- 本地台账是历史快照，最新数据在云端，勿用本地数据推断真实发送/火花结果。

## 十、已知限制与后续方向

- AI 长时间彻底不可用时，开早报的好友当天会跳过（不降级的代价），需手动「立即续火花」补发；日志会点名。
- 云端到 AI 服务商的网络偏慢（区别于生成慢）需部署后用新日志区分「连接超时」还是「读取超时」。
- 火花四态仍依赖抖音图标/DOM，抖音改版可能失效；「🔥 指纹」是校准兜底手段。
- 持续主线（用户长期诉求）：**流畅性、稳定性、移动端可达性、全面模拟用户点测、菜单与页面尺寸统一**。

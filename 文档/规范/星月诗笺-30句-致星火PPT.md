## 三、⚠️ 不要照搬我的选取逻辑（这条比诗词本身重要）

### 我那份是「按日期轮换」

```js
// 星火专注Pro 用的（**不要照抄**）
function poemIndexOfDay(){
  const d=new Date(), seed=d.getFullYear()*372+d.getMonth()*31+d.getDate();
  return seed % STAR_POEMS.length;
}
```

**为什么它在专注Pro 里是对的、在星火PPT 里是错的：**

专注Pro 是**每天打开**的产品，「今日星语」按日期轮换天然合理——今天和昨天不同，明天再变。
而星火PPT 是**一次生成一份**。用日期做种子意味着：

- 同一天生成的两份不同主题的 deck，会拿到**同一句诗**
- 一份商业计划和一份毕业答辩，可能都配上「淡月疏星共寂寥」
- 用户第二次生成时如果还是同一天，还是那句——**看起来像卡住了**

### 正确的选法：按「位置」+「气质」挑，不按日期

**位置决定要不要诗、要几句：**

| 位置 | 用不用 | 说明 |
|---|---|---|
| 封面 | ✅ 用 | 作为题引，配在标题下方一行。**这是最自然的位置** |
| 章节分隔页 | ✅ 用 | 一句诗压住整页留白（若做了 `quote` 版式） |
| 内容页 | ❌ 不用 | 内容页已经信息密集，再加诗是噪音 |
| 封底 | ✅ 用 | 一句作收束，配「谢谢」类文字 |

**一句话原则：一份 deck 最多 3 处（封面 1 + 章节或金句 1 + 封底 1）。多了就从「有味道」变成「贴图」。**

**气质决定用哪一句：**
- 内容**开阔、有雄心**（商业计划 / 愿景）→ 用 **星河** 组
- 内容**温厚、讲人**（团队 / 毕业 / 纪念）→ 用 **人间星语** 或 **月夜**
- 内容**克制、讲方法**（述职 / 学术 / 复盘）→ 用 **疏星淡月**
- 内容**收束、讲下一步**（封底）→ 用 **夜风与晓**（这组天生是「过渡与起承」）

**别硬塞**：如果这份内容是纯数据报告（财务报表、实验数据），**封面题引可以放，正文一句都不要放**。诗是为情绪服务的，没有情绪要服务时就该空着。

### 若要做「不重复」的保证

同一份 deck 内部不重复即可，**不必跨 deck 防重复**——用户下次生成另一份时，换一句反而新鲜。
如果要做，用一个会话级的 `usedPoems` 集合，**按 deck 重置**，不要持久化。

## 四、给你接进 PPT 的三条建议

**① 不要现在就把 30 句全接进去。**
你说「诗词 1 句 → 30 句」，但**真正的价值不是数量，是「挑得对不对」**。建议先只做两个位置：**封面题引 + 封底收束**，各 1 句，跑十来份看效果。位置对了再加章节分隔页。

**② 让 AI 挑，但给它明确的约束，别让它自由发挥。**
在 `DESIGN_RULES` 里加一条，比给它 30 句原文更有效：

```
【题引】封面与封底各可放一句古典星月诗，取自提供的诗库。
选句必须与整份内容的气质一致：开阔用「星河」类，温厚用「人间星语」类，
克制用「疏星淡月」类，收束用「夜风与晓」类。
不要连续两份用同一句；不要为凑诗而选与内容无关的句子。
内容纯为数据/报表时，正文一律不放诗。
```

**③ 注意「出处」要一起放。**
诗的价值一半在出处。只写句子不写作者，会显得像网上随便抄的。我那份的格式是：

```
「醉后不知天在水，满船清梦压星河。」
        唐温如《题龙阳县青草湖》
```

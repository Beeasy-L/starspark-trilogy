## 一、P0 阻塞项（五项，全过才能发）

### P0-1 · 三个 git 仓健康且不分叉

**为什么是 P0**：分叉意味着「本地和远端各有一份别人不知道的改动」，发布时必然互相覆盖。
**2026-10-27 实测就撞到一次**：主仓本地 2 提交 vs 远端 6 提交，同一件分享卡各做一遍。

```powershell
git -C "C:\Users\saucc\Desktop\星火三部曲" fetch origin
git -C "C:\Users\saucc\Desktop\星火三部曲" rev-list --left-right --count HEAD...origin/main
# 期望输出：0	0
```

**三个仓都要查**：
| 仓 | 路径 |
|---|---|
| 介绍页 | `C:\Users\saucc\Desktop\星火三部曲\` |
| 专注Pro | `产品\星火专注Pro\_gitrepo\` |
| PPT deploy | `产品\星火PPT\deploy\网页版\` |

**失败处置**：
- `0  0` → 通过
- `N  0`（本地领先）→ 本地有未推送提交，确认归属后 `git push`
- `0  N`（远端领先）→ `git pull --ff-only`；若不能快进说明分叉
- `N  M`（**双方都有**）→ **分叉，停手**。先 `git log origin/main..HEAD` 和 `HEAD..origin/main` 对比两边内容，**判断哪边是最终版**，不要盲目 merge

**同时查 fsck**：
```powershell
git -C <仓路径> fsck --no-progress
# 期望：无输出 或 仅 dangling 对象（无害）
# 失败：出现 missing / broken link → 该仓对象库损坏，用远端 clone 的 .git 替换
```

## 一、动效的第一原则：先问「该不该动」

沿用 emil-motion 的频率判断表（这是**评审标准**，不是建议）：

| 出现频率 | 决定 |
|---|---|
| 每天 100+ 次（快捷键、命令面板） | **永不动画** |
| 每天几十次（hover、列表导航） | 移除或大幅削减 |
| 偶尔（弹窗、抽屉、toast） | 标准动画 |
| 罕见 / 首次（引导、反馈、庆祝） | **可以加愉悦感** |

> **PPT 场景的落点**：
> - 翻页 / 元素出场 → 每次演示都看 → **标准动画，但可一键全关**
> - 页码、页脚、装饰 → 每天看几十次 → **不做动效**
> - 封面首屏、章节转场 → 罕见 → **可以加仪式感**

**动效的合法目的只有四种**：空间一致性、状态指示、解释、反馈。
「看起来酷」不是合法目的。**这一条对 PPT 尤其重要——最容易滑向特效堆砌。**

## 二、缓动曲线族（直接抄专注Pro）

专注Pro 已上线并验证的 5 条曲线，全部实测自 `_web/index.html`：

```css
:root{
  /* ★ 标准入场（全局默认）—— PPT 元素出场一律用它 */
  --xh-ease-out:    cubic-bezier(.23, 1, .32, 1);    /* L401 引导卡 / L2375 / L2382 */
  /* ★ 火焰类（有机、轻微过冲感） */
  --xh-ease-flame:  cubic-bezier(.16,.84,.36,1);     /* L321 igFlame */
  /* ★ 飞升类（快速离开） */
  --xh-ease-rise:   cubic-bezier(.2,.7,.3,1);        /* L320 igRise */
  /* ★ 飘散类（长尾、衰减） */
  --xh-ease-drift:  cubic-bezier(.12,.7,.3,1);       /* L312 igFw */
  /* 状态切换 */
  --xh-ease-soft:   ease;                           /* L412 / L2375 opacity */
}
```

### 强制规则

| 场景 | 曲线 | 理由 |
|---|---|---|
| **入场 / 出场** | `--xh-ease-out` | ease-out 起步快，感觉更灵敏 |
| **屏幕内移动 / 形变** | `--xh-ease-in-out` | `cubic-bezier(.77,0,.175,1)` |
| **hover / 颜色变化** | `--xh-ease-soft` | |
| **持续运动（loading、转轮）** | `linear` | |
| **默认** | `--xh-ease-out` | |

### 三条硬禁令

1. **UI 动画一律不用 `ease-in`** —— 它起步慢，延迟了用户正在注视的那一刻。
   `ease-out` 在 200ms 下的体感比 `ease-in` 在 200ms 下更快。
2. **禁用 CSS 内置曲线**（`ease` / `ease-in-out` / `ease-in`）作为动画曲线——它们太弱。用上面的自定义曲线。
3. **不要手搓曲线**——曲线来自 `easing.dev` / `easings.co`，或直接复用上面 5 条。

## 三、时长（Duration）

| 元素 | 时长 |
|---|---|
| 按钮按下反馈 | 100–160ms |
| tooltip / 小浮层 | 125–200ms |
| 下拉 / 选择器 | 150–250ms |
| 弹窗 / 抽屉 | 200–300ms |
| **页面内元素出场** | **300–450ms**（PPT 主用） |
| 页面转场 | 350–500ms |
| 封面 / 章节仪式感 | 可到 600–900ms |

> **铁律：UI 动画不超过 300ms。** 180ms 的下拉比 400ms 的感觉灵敏得多。
> PPT 的元素出场可以到 450ms——它是**叙事内容**，不是 UI 控件。

### 三档全局速度（PPT 必须实现）

| 档位 | 系数 | 用途 |
|---|---|---|
| 慢 | 1.4× | 正式汇报、观众需要跟上节奏 |
| **标准** | **1.0×** | 默认 |
| 轻快 | 0.7× | 内部快过、熟练演示者 |

实现方式（不要写死时长）：
```js
document.documentElement.style.setProperty('--xh-speed', '0.7');
```
所有动画时长写成 `calc(420ms * var(--xh-speed, 1))`。

## 四、物理感（Physicality）

### 4.1 绝不用 `scale(0)`

现实中没有东西从「无」出现。起点是 `scale(0.9 ~ 0.97)` + `opacity: 0`。

> **PPT 现状需修**：PPT 没有 `scale(0)` 问题（只有 `xhIn`/`xhFade`），但**新写的元素入场必须遵守此条**。

### 4.2 变换属性只用 transform / opacity

**只动 `transform` 和 `opacity`**——这两个属性不会触发布局重排，60fps 无压力。
**禁止**在动画里动 `width` / `height` / `top` / `left` / `margin` / `box-shadow`。

> 专注Pro 点火仪式的 `igFlame` / `igRise` / `igFw` 全部只动 transform+opacity，值得照抄。

### 4.3 避免父级 CSS 变量驱动子元素 transform

emil-motion 明确点名的问题：父级改了 `--x`，子元素的 transform 跟着跳。
**每个元素用自己声明的 transform**，不要依赖继承的变量。

### 4.4 按下反馈（PPT 交互控件必做）

```css
.xh-btn:active{ transform: scale(.97); transition: transform 160ms var(--xh-ease-out); }
```

## 五、★ 元素出场时序表（PPT 核心，专注Pro 已有范本）

这是「动画编排 Skill」的**真正内核**。原则：**按阅读顺序递进**，不同时炸开。

### 5.1 单页内元素出场顺序

| 序 | 元素 | 建议时长 | 位移 | 说明 |
|---|---|---|---|---|
| 1 | 标题 / 主视觉 | 420ms | `translateY(14px)` → 0 | 先定调 |
| 2 | 副标题 / 说明 | 380ms | `translateY(10px)` → 0 | 紧跟标题，间隔 60ms |
| 3 | 正文要点（逐条） | 340ms | `translateY(8px)` → 0 | **每条间隔 70ms**，递进出现 |
| 4 | 图表 / 数据块 | 480ms | `scale(.97)` + 淡入 | 数据要「长出来」 |
| 5 | 装饰元素 | 600ms | 各自轨迹 | **最后，且可被跳过** |

**硬约束**：
- 同页元素出场总时长 **不超过 1.2s**（超过就该砍内容，不该拖慢节奏）
- 任何单个元素的位移 **≤ 16px**（再大就飘了）
- 要点超过 5 条 → 只做分组递进，不逐条动画

### 5.2 逐条递进的实现（专注Pro L2371–2384 已有同款）

```js
// 参考专注Pro 星链卡片：逐条延迟 + rAF 触发
items.forEach((el, i) => {
  el.style.transition = `opacity .4s var(--xh-ease-soft), transform .45ms var(--xh-ease-out)`;
  el.style.transitionDelay = `${i * 70}ms`;
  el.style.opacity = 0;
  el.style.transform = 'translateY(8px)';
  requestAnimationFrame(() => {
    el.style.opacity = 1;
    el.style.transform = 'none';
  });
});
```

### 5.3 页面转场

| 方向 | 实现 | 时长 |
|---|---|---|
| 前进 | 当前页 `translateX(-2%)` + 淡出 → 新页 `translateX(2%)` → 归位 + 淡入 | 350ms |
| 后退 | 与前进镜像 | 350ms |
| 同页刷新 | 仅交叉淡入淡出 | 240ms |

**铁律**：转场**不做横向滑动超过 3%**，不做 3D 翻转，不做缩放推进——这些是 PPT 模板的廉价感来源。

## 六、禁用清单（明令禁止）

| 禁止 | 原因 |
|---|---|
| `scale(0)` | 违反物理感 |
| 弹跳 / 橡皮筋（overshoot > 5%） | 廉价感 |
| 闪烁 / 频闪 | 视觉疲劳，且触发光敏性风险 |
| 旋转入场 | 除 loading 指示器外无意义 |
| 3D 翻转 / 卡片翻面 | PPT 模板化，破坏克制气质 |
| 粒子 / 爆炸 / 彩带 | 与「安静克制」的星火气质冲突 |
| `ease-in` | 延迟用户注视点 |
| 动画中动 width/height/top/left | 触发布局重排，掉帧 |
| 同一元素 > 2 个 transform 叠加 | 难以调试，易抖动 |

> **星火的气质边界**：动效要**沉稳、克制、有呼吸感**——像火焰升起，不像烟花。
> 专注Pro 的点火仪式是标尺：**0.95s 的 `igFw` 带着余韵消散，比 0.3s 的弹跳高级得多。**

## 七、无障碍（必交付，不是可选项）

### 7.1 `prefers-reduced-motion` 全站支持

```css
@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

> **专注Pro L414 已有等价实现**（针对 `.chain-scroll .star/.link`）。
> **PPT 侧需扩到全站**——目前 PPT 只有 1 处，位置不明。

### 7.2 用户手动关闭（PPT 额外要求）

PPT 是**演示工具**，会投屏、会被打印、会被截图。所以：

- 提供**一键关闭全部动画**开关（不是只跟随系统设置）
- 关闭后：内容**立即呈现**，不残留 `opacity: 0` 的元素
- 关闭状态要**持久化**（localStorage），下次打开沿用

> **这是硬要求**：一个「关掉动画后元素还是看不见」的 bug，会让演示当场失败。

## 十、验收用的自查命令

```bash
# 1. 曲线是否统一（应全部落在 5 条白名单内）
grep -o 'cubic-bezier([^)]*)' 产品/星火PPT/static/index.html | sort -u

# 2. 是否残留 scale(0)
grep -n 'scale(0)' 产品/星火PPT/static/index.html

# 3. reduced-motion 是否全站覆盖
grep -c 'prefers-reduced-motion' 产品/星火PPT/static/index.html

# 4. 动画时长是否写死（应改用 calc + --xh-speed）
grep -n 'animation:[a-zA-Z]* [0-9.]*ms' 产品/星火PPT/static/index.html
```

### ★ 实测基线（2026-10-26，落地前现状）

跑完上面 4 条的**实测结果**，作为改造前的对照：

| # | 检查项 | 实测值 | 判定 |
|---|---|---|---|
| 1 | `cubic-bezier` 取值 | **只有 1 种**：`cubic-bezier(.2,.7,.3,1)` ×7 | ⚠️ 曲线**意外统一**，但它是专注Pro 的 `--xh-ease-rise`（飞升曲线），**不是入场该用的 `--xh-ease-out`**。等于全站用了一条「快速离开」的曲线做入场 |
| 2 | `scale(0)` | **0 处** | ✅ 无问题 |
| 3 | `prefers-reduced-motion` | **1 处**：`@media (prefers-reduced-motion: reduce){ .page *{animation:none !important} }`（L247） | ⚠️ 只覆盖 `.page` 内的 animation，**未覆盖 transition**，弹层/控件/侧栏不在范围内 |
| 4 | 写死时长 | `xhIn .42s`×3、`xhIn .5s`×2、`xhIn .45s`×1、`xhIn .40s`×1、`xhFade .6s`×1、`rot .8s`×1 | ❌ **同一个 `xhIn` 出现 4 个不同时长**（.40/.42/.45/.5s），完全没有节奏规范 |

**这四条实测说明三件事**：

1. **曲线不用改结构，只需换取值**——全站只有 1 条，改起来是零风险的批量替换。
2. **时长是真正的病灶**——同一个动画 4 个时长，说明是「随手写」而非「有谱」。必须先立 §三 的时长表。
3. **`reduced-motion` 覆盖面不足**——`.page *` 只管了动画没管过渡，关闭后可能出现「元素还在 transition 中」的不一致。

> **落地顺序建议**：先修 3（reduced-motion 覆盖面）→ 再修 4（时长统一 + `--xh-speed`）→ 再修 1（曲线换 `--xh-ease-out`）→ 最后做 P1 编排层。
> 理由：3 和 4 是**无风险改动**，1 是批量替换，只有 P1 编排层是新写代码，风险最高放最后。
